# 《课间十分钟》设计方案

> 初中校园主题 · 像素风 · 剧情 / 模拟养成 · 单人
> 文档版本：v0.1（M0 阶段）· 最后更新：M0

## 1. 一句话定位

你是初一新生，在教室、走廊、操场之间度过三年。每一节课间都可能发生点什么——
突击考试、和同桌翻脸、老师抽风布置一整本练习册。你的选择会写进属性、关系和结局。

## 2. 技术选型（已定稿）

| 层 | 选型 | 理由 |
| --- | --- | --- |
| 构建 | Vite 5+ | 快、约定少、下一位 AI 无需额外学习成本 |
| 语言 | TypeScript（strict） | 类型即文档，利于长期迭代与 AI 交接 |
| 渲染 | 原生 Canvas 2D + DOM 覆盖层 | 像素画面走 Canvas，中文文本走 DOM（中文像素字体不可程序化生成，DOM 文本天然清晰、可缩放、可复制） |
| 框架 | 无（原生 DOM + 模块化场景类） | 依赖最少，未来升级不易被生态变更打崩 |
| 后端 | `server/index.mjs`，Node 内置 http，**零依赖** | 仅做两件事：托管 `dist/` 静态资源 + `/api/llm` 代理，保护 API Key |
| 存档 | localStorage + JSON 导入导出 | 单机零后端依赖 |
| 美术 | **全部程序化生成**（调色板 + 图块 + 精灵绘制代码） | 零外部素材、零版权风险、体积小 |
| 音效 | WebAudio 实时合成 8-bit 音 | 同上，可开关 |

### 为什么中文不用像素字体

汉字字形无法用少量代码程序化生成。方案是**双层结构**：

- `#stage`（Canvas）：场景、精灵、立绘、粒子等纯图形
- `#overlay`（DOM）：对话框、菜单、属性面板等所有文本

DOM 层用 CSS 变量 `--font-pixel` 指定字体链，优先尝试像素中文字体（如本机已安装的
Zpix / 缝合像素字体 / 微软雅黑），失败时回退到系统字体，布局不塌。若日后要极致像素感，
再往 `public/fonts/` 放一份开源（OFL）像素中文字体子集并在 CSS 里声明即可，**不需要改任何逻辑代码**。

## 3. 目录结构

```
新游戏/
├─ index.html              入口外壳：#stage + #overlay
├─ vite.config.ts          构建配置（base:'./'，/api 代理到 8787）
├─ tsconfig.json           严格模式 + @/* 路径别名
├─ server/
│  ├─ index.mjs            零依赖 Node 服务：静态托管 + /api/llm 代理
│  └─ .env.example         API Key / BaseURL / 模型名模板
├─ docs/
│  ├─ 设计方案.md          本文档
│  ├─ 开发日志.md          每步一条记录（按时间追加，最新在最后）
│  └─ 交接文档.md          给下一位 AI 的接手说明
└─ src/
   ├─ main.ts              程序入口
   ├─ app/                 应用层：路由、状态、存档、设置、随机数、事件总线
   ├─ game/                玩法层：类型、事件引擎、学期推进、属性、关系
   ├─ data/                内容层：事件库、预设角色、性格标签、外观部件
   ├─ ai/                  AI 层：客户端、提示词、JSON 校验、生成器、NPC 对话
   ├─ render/              渲染层：画布、调色板、精灵、图块、像素 UI 工具
   ├─ scenes/              场景层：启动、主菜单、角色工坊、游玩、设置、图鉴
   └─ styles/              样式：全局变量、像素 UI、响应式
```

分层规则（**改代码时请遵守**）：

1. `scenes/` 可以依赖下面所有层；`render/` 和 `data/` **不得**反向依赖 `scenes/`。
2. `game/` 不碰 DOM、不碰 Canvas，纯数据与逻辑，便于单测与 AI 生成内容校验。
3. `ai/` 只负责"把自然语言变成符合 schema 的数据"，**不得**直接改游戏状态。

## 4. 玩法设计

### 4.1 核心循环

```
学期阶段 → 周 → 每天 5 个时段 → 每时段 1~2 个事件 → 玩家选择 → 属性/关系变化
   ↑                                                                    ↓
   └──────────── 期末考结算 → 升入下一阶段 / 触发结局 ←── 周末结算 ←──┘
```

时段：早自习 / 上午课 / 午休 / 下午课 / 晚自习。

### 4.2 游戏阶段（主界面可选）

| 阶段 | 主题 | 事件池特征 |
| --- | --- | --- |
| 初一 | 适应新环境 | 温和，正向权重高，认识新同学 |
| 初二 | 分水岭 | 争执、叛逆、暗恋、偏科事件增多 |
| 初三 | 中考压力 | 作业爆炸、突击考试、月考排名权重拉高，结局判定更严 |

### 4.3 属性

主角：学业 / 体力 / 心态（压力）/ 人气 / 老师好感 / 家庭期望 / 零花钱。
关系：每个 NPC 独立好感度 -100 ~ 100，影响可出现选项与事件分支。

### 4.4 随机剧情系统（双模式，AI 为主）

**模式 A：本地模板库（保底，永不失败）**

```
Event {
  id, phase[], slots[], weight, cooldown,
  require: { stat>=x, relation>=y, flags[] },
  title, text, choices[{ text, require?, effects{} }]
}
```

- 加权随机 + 冷却 + 坏事件保底（不允许连续 3 个负面事件）
- 首批 40~60 条内建事件，覆盖三个阶段

**模式 B：AI 动态生成（主力）**

- 按当前阶段 / 时段 / 属性 / 在场角色，生成从未出现过的新事件与选项
- 严格 JSON Schema 约束：只允许既定属性字段、既定角色 id、数值区间受限
- 同时支撑"NPC 自由对话"（玩家可打字与角色聊天）
- 任何失败（无 Key / 超时 8s / 解析失败 / 校验不通过）→ **自动降级到模式 A**，
  玩家侧只看到一句"这次没什么特别的"，游戏永不卡死

### 4.5 角色系统

- **主角创建**：姓名、性别、外观（发型/发色/肤色/校服/配饰像素部件拼装）、性格标签 → 影响初始属性与选项加成
- **NPC 创建/编辑**：姓名、身份、性格标签、初始好感、外观、一句话人设
- 预设角色库一键套用；也可让 AI 依据一句描述补全人设
- 所有角色随存档保存，事件触发时按条件筛选"谁参与"

## 5. 平台适配

**画面层与界面层解耦**（重要）：

- `#stage`（Canvas）：内部分辨率固定 `320×180`，等比缩放到视口内。
  空间够时取**整数倍**（≥2 倍），手机上退化为小数倍以尽量占满宽度。
- `#overlay`（DOM）：**始终铺满整个视口**，不再跟着画布缩放。
  竖屏时给画布留出顶部一条带（CSS 变量 `--stage-h`），界面从带下面开始。

> 为什么这样做：早期版本让 overlay 跟画布同尺寸，结果 390×844 的手机上界面只剩 219px 高，
> 完全没法用。解耦后竖屏手机 UI 有 600+px 可用高度，横屏/桌面下两者视觉上仍然重合。

响应式断点：`< 640px` 手机竖屏（卡片单列、纵向堆叠）、`640~1024` 平板、`> 1024` 桌面。
触屏：按钮热区 ≥ 44px；键盘：↑↓/WS 选择、Enter/空格 确定、Esc 返回；输入框内的按键不冒泡给场景。

## 7. 风险与对策

| 风险 | 对策 |
| --- | --- |
| AI 输出不稳定 | JSON Schema 强约束 + 字段白名单 + 校验失败重试 1 次后降级 |
| 题材边界（角色是初中生） | 提示词全程限定校园日常；禁止恋爱露骨、暴力、不良引导；输出过敏感词过滤 |
| API Key 泄露 | Key 只存在服务端 `.env`；前端设置页填的 Key 仅存本机 localStorage，仅供开发者自测 |
| 分享给同学时无服务器 | 支持纯静态部署：此时同学填自己的 Key 或走本地模板模式 |
| 素材版权 | 全部程序化生成，不引入第三方素材 |
