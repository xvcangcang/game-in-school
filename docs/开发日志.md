## M6 · AI 集成：代理服务 / 事件生成 / NPC 对话 / 降级与熔断（2026-01-01）

**做了什么**

- `server/index.mjs`：**零依赖** Node 服务。静态托管 `dist/`（含单页回退与目录穿越防护）
  ＋ `POST /api/llm` 代理 ＋ `GET /api/health`。Key 只存在服务端，前端拿不到
- `server/.env.example`：`LLM_BASE_URL` / `LLM_MODEL` / `LLM_API_KEY` / `PORT` 模板
- `ai/client.ts`：模型调用唯一出口。支持「走本站代理」和「浏览器直连」两种模式，
  统一超时（AbortController）、统一错误码（NO_KEY / TIMEOUT / NETWORK / UPSTREAM / BAD_RESPONSE），
  并带 **熔断**：没配 Key 时不会每个时段都白发一次请求
- `ai/prompts.ts`：事件生成提示词（含题材边界与 JSON 结构）、NPC 对话提示词、连通性测试提示词。
  上下文里带上当前学段/时段/属性/人设/最近剧情，并要求不要重复最近出现过的事件标题
- `ai/schema.ts`：**安全底线**。结构错误整条丢弃；数值越界夹取、非法属性键与不存在的角色 id 直接剔除；
  一次改超过 4 项属性会被截断
- `ai/generator.ts`：草稿 → `GameEvent`；校验失败带上原因重试一次，仍失败返回 null 交给上层降级
- `ai/chat.ts`：NPC 自由对话（按角色保存会话历史）+ `pingAi()` 连通性测试
- `scenes/play.ts`：接入「AI 优先、失败静默降级」的主循环；
  新增「正在编剧情」动画、AI 内容角标、右上角「说话」按钮与聊天面板
- `scenes/settingsScene.ts`：「测试连接」按钮接真实请求
- `tools/mock-llm.mjs`：假模型服务，**不用真 Key、不烧额度**就能把整条 AI 链路跑通
- `README.md` 重写：区分「开发」「正式玩（含服务端 Key）」「纯静态分享」三种用法

## 附二 · 音效重做 + 「说话」入口挪位置（用户反馈）

**用户反馈**：①「音频乱七八糟的」 ②「说话藏在上面太反知觉了，放在回复栏里第一条」

### ① 音效：根因不是音量，是一个死循环

查下来有三个叠加的问题，其中第一个是我自己写的 bug：

1. **菜单悬停会把整个列表 `clear()` 重建**。光标下的按钮被销毁又新建，浏览器会再派发一次
   `mouseover` → 再次重建 → 无限循环。表现就是划过菜单时音效变机关枪，CPU 也白烧。
   修法：`createMenuList` 里拆出 `syncActive()`，**只改 class，绝不重建 DOM**。
2. **打字机音每 5 个字响一次**。正常速度约 45 字/秒 ≈ 每秒 9 个 1400Hz 方波，纯粹的噪音。
   改成：每 12 个字一次、只在慢速/常速播、并改用**噪声脉冲 + 高通**（比方波柔和得多）。
3. **上课铃每个时段都敲**。几秒响一次，谁受得了。改成只在跨天时响一次。

顺带把整个音频引擎重做了一遍：

- 音频图 `voice → 低通 → 母线 → 限幅器 → 输出`。低通削掉方波最扎耳朵的高频，
  限幅器兜住峰值，多声部叠加不再削波爆音
- **复音数上限 8**：超了直接丢弃新声音，宁可少响也不要糊成一片
- **每个音效独立节流**（悬停 120ms、点击 60ms、打字 110ms…），并统计被拦下的次数
- 包络改成「快起音 + 软收音」，消除方波头尾的"啪"声
- 新增 **音效音量** 设置项（默认 50%）+ 设置页的 **「试听全部音效」** 按钮
- 音频开关直接映射到母线增益，关掉时正在响的也会立刻安静

**新增工具 `tools/audiotest.mjs`**：音频截图看不出来，只能靠计数。
它模拟「鼠标在菜单上来回扫 20 遍」和「连玩 6 个时段」，输出实际发声频率并自动判定合格线。

| | 修复前 | 修复后 |
| --- | --- | --- |
| 菜单悬停（人工极速扫动 20 遍） | 无上限循环（机关枪） | 7.3 个/秒，其中 100 次被节流拦下 |
| 游玩 6 个时段 | — | 1.3 个/秒，无复音堆积 |

> 注意：测试脚本本身也踩了个坑——`page.evaluate(() => 'window.__game.audioStats()')`
> 传的是「返回字符串字面量」的函数，puppeteer 会把字符串原样返回，字段全是 `undefined`，
> **测试会假通过**。必须传真正在页面里求值的函数。

### ② 「说话」入口：从顶栏挪到回复栏第一条

原来它挂在顶栏最右边，而玩家的视线焦点在对话框上，根本不会往那儿看。

现在它是**选项列表的第一条**，用绿色区分（和黄色的剧情选项编号一眼分得开）：
「话　和林小雨说句话」。在场有多人时会列多条（最多 3 条）。

两个细节：

- 它**不参与数字键编号**：`1/2/3` 始终留给真正的剧情选项，聊天用 `T` 键或直接点，
  避免"想选第一个选项却打开了聊天"
- 打字机还在播时，剧情选项是灰的，但**「说话」始终可点**——想找同学聊天不该被文字速度挡住

## 附三 · 「说完话之后怎么办」—— 聊完继续剧情（用户反馈）

**用户反馈**：「说完话怎么办呢，应该加个继续剧情按钮（可以把硕大的发送键一分为二），

原来的聊天面板只有「发送」和「✕」，聊完只能关掉面板回到原来的选项，**这段对话白聊了**。

**做了什么**

1. **发送键一分为二**：底部一行变成 `[输入框] [发送] [继续剧情]`，
   发送键收窄到 68px，「继续剧情」用绿色区分。窄屏时输入框独占一行、两个按钮平分下一行。
   面板底部加了一行说明，告诉玩家这个按钮是干什么的。
2. **`ai/prompts.ts` 新增 `buildChatFollowUpPrompt()`**：把「刚才那一幕（标题/正文/原选项）」
   + 「玩家与某角色的对话记录」一起交给模型，要求它接着往下写，并给出一组**不重复**的新选项，
   且对话里已经说定的事必须体现在新剧情里。
3. **`ai/generator.ts` 抽出 `requestValidatedEvent()`**，事件生成与「聊完续写」共用同一条
   「请求 → 解析 → schema 校验 → 转 GameEvent → 可选项非空」流水线，
   两条路的质量标准完全一致。新增 `generateFollowUpFromChat()`。
4. **`scenes/play.ts` 新增 `continueFromChat()`**：
   - 落点是**接替当前这一幕，不推进时段**（它不是"又过了一段时间"）
   - 生成期间面板里显示「AI 正在把这段对话接进剧情……」，两个按钮置灰
   - 失败就弹提示并退回原来的选项，玩家不会卡住
   - **没开 AI 时按钮文案变成「回到剧情」**，只负责关掉面板，不误导玩家

## 附四 · 角色工坊进不去阵容页 + 主角身份（用户反馈）

**用户反馈**：「角色工坊现在只能编辑主角，改不了同学，修复，再加个主角身分自定义（输入框），和同学一样的」

### bug①：工坊模式走进了死胡同

`renderBody()` 里 `step` 只由「上一步 / 下一步」按钮驱动，而那两个按钮的条件是
`mode === 'new'`。**工坊模式下没有任何分步导航，`step` 永远停在 0**，
`buildRosterStep()` 根本到不了——玩家只能看到主角那一页，而工坊模式下主角的改动
又不会保存（`saveRoster` 只存 NPC），纯属死胡同。

修法：**工坊模式直接进阵容页**，不再走主角的三步流程。页头补了一句
「主角在『新游戏』里创建」，把两件事的职责说清楚。

### 需求②：主角可以自定义身份

新增 `Character.title?: string` —— **自由填写的身份**，和 `role` 分工明确：

- `role` 是给引擎和事件库用的枚举（同学/同桌/班主任…），决定说话口气、能否参与某类事件
- `title` 是给玩家看、也喂给 AI 当上下文的自由文本（「转学生」「班长」「隔壁班来借书的」）

改动覆盖：

- `game/character.ts`：`defaultTitleFor()`（主角默认「学生」，NPC 默认用 role 名）、
  `displayTitle()`；`describeCharacter()` 改用 title，所以 AI 提示词自动带上
- `scenes/creation.ts`：新游戏第一步加「身份」输入框；NPC 编辑器把原来的
  「身份」下拉改名「身份类别」，另加一个自由填写的「身份」输入框；阵容列表显示身份，
  并且**身份和类别同名时不再重复显示**（原来是「同桌 同桌」）
- `app/roster.ts` / `game/newGame.ts`：持久化与传递 title
- **存档版本 1 → 2**，`app/save.ts` 补上第一条真实的迁移函数：按 role 给老角色补默认身份。
  这是 MIGRATIONS 从建立起第一次真正被用到（之前是空表，等于没测过）
